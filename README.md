# World Copies Everything (Fabric Edition)

A Java Fabric port of the original Bedrock script pack: **Minecraft But The World Copies Everything**.

Every block a player **PLACES**, **BREAKS**, or **ALTERS** is duplicated **INFINITELY** across the world, repeating every 16 blocks on the X and Z axes. 

## Credits
This mod is a faithful Java/Fabric port of the original Bedrock Script API pack created by **TheLake — ThreeDonkeys studio**. All core design concepts, parity rules, and the general mechanic design belong to them.

## Implementation Details

The core mechanics of the reference project are fully implemented:
* **Infinite Repeating Grid**: Changes are recorded and stamped across all chunks in real-time as you explore.
* **Block Interactions**: Doors, levers, stripped logs, tilled dirt, etc., are all replicated.
* **Multi-blocks & Grown Structures**: Beds, tall plants, and bone-mealed trees copy atomically without breaking.
* **Fluids**: Water and lava flow naturally at the copied locations (proper block state ticks).
* **Mobs**: Naturally spawned and bred mobs are mirrored to adjacent cells (they expire safely to prevent world bloat).
* **Portals**: Lighting Nether Portals or completing End Portals will open the portals across all copies simultaneously.
* **Jukeboxes & Redstone**: Music discs echo to nearby copies. Redstone switches (levers, buttons) are copied, allowing the local redstone circuits at the copies to fire independently.
* **NBT Data**: Banners, skulls, decorated pots, lecterns, and sign text/colors are perfectly matched.

### Technical Differences & What is NOT implemented

Due to fundamental engine differences between Minecraft Bedrock and Java Edition, the following adaptations were made:

* **Dyed Cauldron Water**: **Not implemented**. In Bedrock, cauldrons hold custom dyed water via NBT data. In Java Vanilla, cauldrons only hold water, lava, or powder snow (using distinct blocks/states). There is no native support for custom dyed water inside cauldrons.
* **Chest/Inventory Syncing**: **Not implemented (Intended)**. Just like the final version of the original Bedrock pack, syncing inventory contents was removed on purpose to prevent massive item duplication exploits. Chests, barrels, and shulker boxes copy as empty blocks.
* **Paintings**: **Not implemented (Intended)**. Explicitly excluded from being copied to prevent catastrophic entity-lag loops, matching the original pack's behavior.
* **Item Frames**: In Bedrock, item frames are *blocks*. In Java, they are *entities*. The mod adapts this by tracking entity interactions to ensure frames, their items, and rotations are perfectly copied.
* **Timing of Jukebox Echoes**: In Bedrock, the music echo fires in the exact same tick as the interaction. In Java, there is a deliberate 1-tick delay to ensure the Jukebox BlockEntity has successfully updated its internal state with the music disc before playing the sound to clients.

## Contributing

We welcome community contributions! If you'd like to help improve the mod, please follow these guidelines:

### Reporting Issues
* Check the existing issues to ensure it hasn't been reported yet.
* Provide clear steps to reproduce the issue.
* Include your Minecraft version, Fabric Loader version, and the mod version.
* If it's a crash, please provide the full crash report via a Pastebin link.

### Pull Requests (PRs)
* Fork the repository and create your branch from `main`.
* Ensure your code follows standard Java naming conventions and Fabric modding practices.
* Test your changes thoroughly in-game before opening a PR.
* Provide a clear and descriptive title and description for your PR.

## Local Development Setup

To set up the workspace and start contributing to the mod:

1. **Clone the repository**:
   ```bash
   git clone https://github.com/mmlo/worldCopiesEverything.git
   cd world-copies-everything
   ```

2. **Generate Sources (Optional but recommended)**:
   This will download the Minecraft source code and map it so your IDE can read it.
   ```bash
   # On Linux/macOS
   ./gradlew genSources
   # On Windows
   gradlew genSources
   ```

3. **Import into your IDE**:
   * **IntelliJ IDEA** (Recommended): Open the project folder. IntelliJ will automatically detect the Gradle project and import it.
   * **Eclipse**: Run `./gradlew eclipse` then import the project into your workspace.

4. **Run the Game**:
   You can run the client directly from your IDE using the `Minecraft Client` run configuration generated by Fabric Loom.
   Alternatively, via terminal:
   ```bash
   ./gradlew runClient
   ```

5. **Build the Mod**:
   To compile the mod into a `.jar` file for distribution:
   ```bash
   ./gradlew build
   ```
   The compiled JAR will be located in the `build/libs/` folder.
